Хеш-таблица Rust связывает ключи со значениями. В этом уроке вы создадите `HashMap`, прочитаете запись и измените её через ссылку. Отсутствие ключа обработаете через знакомый `Option`.

Тип находится в стандартной библиотеке. Подключите его через `use std::collections::HashMap;`. В `HashMap<String, i32>` первый параметр задаёт тип ключа, второй тип значения.

```rust
use std::collections::HashMap;

pub fn scores() -> HashMap<String, i32> {
    let mut scores = HashMap::new();
    scores.insert(String::from("Alice"), 10);
    scores.insert(String::from("Bob"), 7);
    scores.insert(String::from("Alice"), 12);
    scores
}
```

Метод `insert` добавляет запись. Если ключ уже был, он заменяет значение и возвращает прежнее в `Some`. Для нового ключа возвращается `None`. В примере остаются две записи, у `Alice` значение равно `12`. Ключ типа `String` передаётся таблице во владение.

Метод `get` возвращает `Option` с общей ссылкой на значение.

```rust
pub fn score_or_zero(scores: &HashMap<String, i32>, name: &str) -> i32 {
    match scores.get(name) {
        Some(score) => *score,
        None => 0,
    }
}
```

Для поиска по ключу `String` можно использовать `&str`. Поэтому не требуется создавать новую строку только ради вызова `get("Alice")`. Метод `contains_key` проверяет наличие записи, а `len` возвращает число записей.

Метод `get_mut` принимает изменяемый доступ к таблице и возвращает `Option<&mut i32>`. Внутри ветви `Some(value)` запись `*value = ...` меняет существующую запись. Если ключа нет, `get_mut` вернёт `None` и ничего не добавит. Обычная индексация отсутствующего ключа вызвала бы панику, поэтому для ожидаемого отсутствия используйте `get` или `get_mut`.

Таблица не гарантирует порядок обхода. Проверять результат следует по парам ключей и значений. Вывод в одном конкретном порядке не является свойством `HashMap`.
