Rust связывает освобождение памяти с владельцем значения. В этом уроке вы проследите перемещение `String` и создадите независимую копию через `clone`. Это объяснит, почему привычное присваивание иногда делает исходную переменную недоступной.

У значения `String` есть владелец. Когда владелец выходит из области видимости, Rust освобождает буфер строки. Передача такой строки в новую переменную обычно перемещает владение.

```rust
pub fn show_title() {
    let title = String::from("Rust");
    let saved = title;
    println!("{}", saved);
}
```

После `let saved = title;` использовать `title` уже нельзя. Сам буфер не копируется, право управлять им переходит новой переменной. Так Rust предотвращает повторное освобождение одной памяти. Следующий фрагмент не скомпилируется.

<!-- lint-code-blocks: skip — обращение к перемещённой строке намеренно не компилируется -->
```text
let title = String::from("Rust");
let saved = title;
println!("{}", title); // error: borrow of moved value
```

Передача аргумента типа `String` в функцию тоже перемещает владение. Возврат `String` передаёт его вызывающему коду. Для независимой копии вызовите `title.clone()`. Копирование буфера требует времени и памяти, поэтому не стоит добавлять `clone` только ради устранения каждой ошибки компилятора. В следующем уроке мы передадим доступ к строке без её копирования.

У чисел `i32`, `usize`, значений `bool` и `char` другое поведение. Они поддерживают `Copy` и копируются при присваивании. Например, после `let other = count;` обе переменные с `i32` остаются доступны. Копирование и перемещение определяются типом значения.

На схеме показано состояние после перемещения. Единственный владелец буфера теперь называется `saved`.

```text
До let saved = title:
  title ──владеет──> ["Rust"]

После let saved = title:
  title (недоступна)
  saved ──владеет──> ["Rust"]
```

Перемещение не создаёт второй буфер. Вызов `clone` создал бы отдельный буфер с тем же текстом, и у каждого буфера был бы свой владелец.
