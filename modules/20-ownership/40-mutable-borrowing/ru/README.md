Чтобы функция изменила строку вызывающего кода, ей передают `&mut String`. В этом уроке вы создадите изменяемую ссылку и разберёте ограничение на одновременный доступ. Владение строкой при этом останется у вызывающей функции.

В примере `mut` встречается в трёх местах. Объявление владельца разрешает менять значение, тип параметра требует изменяемую ссылку, а `&mut title` создаёт эту ссылку при вызове.

```rust
pub fn clear_title(text: &mut String) {
    text.clear();
}

pub fn show_title() {
    let mut title = String::from("Rust");
    clear_title(&mut title);
    println!("{}", title);
}
```

После вызова `title` содержит пустую строку. Метод `clear` удаляет весь текст. Метод `push` добавляет один `char`, а `push_str` дописывает текст из другой строки. Функция ничего не возвращает, потому что меняет существующее значение через ссылку.

Пока изменяемая ссылка используется, Rust запрещает другие обращения к тем же данным, которые конфликтуют с ней. В частности, нельзя одновременно использовать две изменяемые ссылки или изменяемую и общую. Следующий фрагмент не скомпилируется, потому что первая ссылка нужна после создания второй.

<!-- lint-code-blocks: skip — две изменяемые ссылки используются одновременно -->
```text
let mut title = String::from("Rust");
let first = &mut title;
let second = &mut title;
first.push_str("!");
second.push_str("?");
```

Таблица сравнивает доступ к одному значению в тот период, когда обе ссылки ещё нужны для последующих действий.

| Две ссылки на одни данные | Допустимы вместе |
| --- | --- |
| `&T` и `&T` | Да, обе позволяют читать |
| `&mut T` и `&T` | Нет, изменение конфликтует с общим чтением |
| `&mut T` и `&mut T` | Нет, оба доступа разрешали бы изменение |

Заимствование обычно заканчивается после последнего использования ссылки. Поэтому два последовательных вызова `clear_title(&mut title)` допустимы. Первый вызов завершает свой доступ до начала второго. Это ограничение позволяет компилятору исключить конфликтующие изменения данных.
