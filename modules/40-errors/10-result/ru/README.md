Иногда нужно вернуть причину неудачи, чтобы вызывающий код мог выбрать действие. В этом уроке вы опишете результат через `Result<T, E>` и обработаете ошибку через `match`. Отказ станет обычным значением, которое можно передать дальше.

Тип `Result<T, E>` имеет варианты `Ok(T)` и `Err(E)`. Первый тип задаёт полезный результат, второй задаёт ошибку. Например, `Result<i32, String>` содержит число при успешном вычислении. При ошибке он содержит текст с её описанием.

В прошлом уроке поиск по индексу возвращал `Option`. Добавим к отсутствию элемента сообщение об ошибке.

```rust
pub fn checked_at(values: &[i32; 3], index: usize) -> Result<i32, String> {
    match values.get(index) {
        Some(value) => Ok(*value),
        None => Err(String::from("index out of bounds")),
    }
}
```

Вызов `checked_at(&[10, 20, 30], 1)` вернёт `Ok(20)`. Для индекса `3` функция вернёт `Err` с пояснением. Сам возврат ошибки не прерывает программу. Вызывающий код решает, что делать дальше.

```rust
pub fn show_at(values: &[i32; 3], index: usize) {
    match checked_at(values, index) {
        Ok(value) => println!("{}", value),
        Err(message) => println!("Error: {}", message),
    }
}
```

У `Result` требуется обработать оба варианта. В примере ошибка превращается в текстовый вывод, но другая функция могла бы вернуть её дальше или выбрать запасное значение.

Паника означает другой путь завершения и не превращается автоматически в `Err`. Например, индексация за пределами массива вызывает панику. Вызов `unwrap()` у результата тоже паникует на `Err`, поэтому он не заменяет обработку ожидаемого отказа.

Если функция выполняет арифметику, её контракт должен назвать допустимый диапазон. Целочисленное деление требует учитывать ноль в знаменателе и редкий случай переполнения минимального числа при делении на `-1`. В упражнении диапазон исключает переполнение, а ноль нужно обработать как обычную ошибку.
