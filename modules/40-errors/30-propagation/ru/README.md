Несколько операций с `Result` можно соединить без вложенного `match` на каждом шаге. В этом уроке вы используете оператор `?`, чтобы получить полезное значение либо передать ошибку дальше. Тип отказа останется частью сигнатуры.

Оператор `?` извлекает содержимое `Ok`. Если получен `Err`, текущая функция сразу возвращает ошибку. Следующие строки не выполняются.

```rust
pub fn require_text(text: &str) -> Result<&str, String> {
    if text.is_empty() {
        Err(String::from("text is empty"))
    } else {
        Ok(text)
    }
}

pub fn title_length(text: &str) -> Result<usize, String> {
    let title = require_text(text)?;
    Ok(title.len())
}
```

Если `require_text` вернул `Ok`, переменная `title` содержит сам срез `&str`. Для пустой строки `title_length` сразу вернёт `Err` с исходным сообщением. Оператор не вызывает панику, ошибка передаётся вызывающему коду.

У обеих функций тип ошибки равен `String`. Для передачи ошибок другого типа может понадобиться преобразование. Например, стандартный `parse::<i32>` возвращает `ParseIntError`. В прошлом уроке мы преобразовали его через `match`, после чего можно работать с одинаковыми типами ошибок. Написать `text.parse::<i32>()?` внутри функции с `Result<..., String>` без такого преобразования не получится.

## Передача отсутствующего значения

У `Option` оператор `?` извлекает значение из `Some` или возвращает `None`. Сама функция тоже должна возвращать `Option`.

```rust
pub fn at(values: &[i32; 3], index: usize) -> Option<i32> {
    let value = values.get(index)?;
    Some(*value)
}
```

За пределами массива `get` вернёт `None`, и `at` передаст его дальше. В функции с результатом `i32` таким способом передать `None` нельзя. Сигнатура должна позволять выразить этот исход.

Если несколько проверок стоят подряд, порядок вызовов определяет первую возвращаемую ошибку. Поэтому вызывающий код получает первую ошибку в порядке указанных проверок.
