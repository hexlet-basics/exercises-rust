Метод `parse` превращает текст в число и возвращает результат, который может содержать ошибку. В этом уроке вы укажете целевой тип и преобразуете ошибку разбора в ответ своей функции. Допустимость числа для задачи проверите отдельно после разбора.

Компилятору нужно знать, какой числовой тип требуется получить. Его можно указать у переменной результата.

```rust
pub fn parse_number(text: &str) -> Result<i32, String> {
    let parsed: Result<i32, _> = text.trim().parse();
    match parsed {
        Ok(number) => Ok(number),
        Err(_) => Err(String::from("not a number")),
    }
}
```

Метод `trim` возвращает срез без пробельных символов по краям. Например, `" 42 "` превращается в `"42"`. Внутренние пробелы остаются. Затем `parse` пытается получить `i32`.

Подчёркивание в аннотации `Result<i32, _>` позволяет вывести конкретный тип ошибки стандартной библиотеки. В данном случае это `std::num::ParseIntError`. В ветви `Err(_)` мы отбрасываем его содержимое и создаём сообщение типа `String`. Так интерфейс функции возвращает один выбранный тип ошибки.

Другая форма указания типа имеет вид `text.parse::<i32>()`. Запись `::<...>` задаёт параметр типа у метода. Своим обобщённым функциям посвятим отдельный урок, а сейчас достаточно уметь читать вызов стандартного метода.

Пустая строка, дробная запись и число вне диапазона `i32` дадут ошибку разбора. Строка `"-2"` успешно разбирается как отрицательное целое. Подходит ли оно в качестве количества, решает уже ваш код.

Для проверки диапазона после `Ok(number)` можно использовать обычный `if`. Например, запись `(0..=59).contains(&number)` проверяет допустимое число секунд с включением обеих границ. В условии упражнения различайте ошибку формата и отказ по правилам задачи. Это позволяет вызывающему коду сообщить конкретную причину.
